# S3 (`amazonSimpleStorageServiceGroup` group)

S3 is a **group** service: the line item has `subServices: [...]` rather than top-level `calculationComponents`. Each storage class is its own sub-service; data transfer is a separate sub-service.

## Group-level header

```json
{
  "serviceCode":  "amazonSimpleStorageServiceGroup",
  "estimateFor":  "simpleStorageServiceClassesGroup",
  "version":      "0.0.85",
  "region":       "<code>",
  "regionName":   "<display>",
  "serviceName":  "Amazon Simple Storage Service (S3)",
  "description":  null,
  "subServices":  [ ... see below ... ],
  "serviceCost":  { "monthly": <sum of subServices.serviceCost.monthly>, "upfront": 0 },
  "configSummary": "S3 Standard storage (<N> GB per month), ..."
}
```

## subService shapes by storage class

Each sub-service uses the flat per-line-item shape (no nested calculationComponents wrapper, just the fields).

### S3 Standard

```jsonc
{
  "serviceCode":  "amazonS3Standard",
  "estimateFor":  "s3Standard",
  "version":      "0.0.71",
  "region":       "<code>",
  "description":  null,
  "calculationComponents": {
    "moveToStorageClassMethod": {"value": "No movement required"},   // No movement required | Lifecycle | Manual
    "s3StandardStorageSize":    {"value": "1000", "unit": "gb|month"} // GB-month
  },
  "serviceCost": { "monthly": <computed>, "upfront": 0 }
}
```

Other classes follow the same pattern with their own field name:

| serviceCode | estimateFor | size field name |
|---|---|---|
| amazonS3Standard | s3Standard | s3StandardStorageSize |
| amazonS3StandardInfrequentAccess | s3StandardInfrequentAccess | s3SiaStorageSize |
| amazonS3IntelligentTiering | s3IntelligentTiering | (multiple bands; capture HAR before promising) |
| s3OneZoneInfrequentAccess | s3OneZoneInfrequentAccess | s3OneZoneIaStorageSize |
| s3GlacierInstantRetrieval | s3GlacierInstantRetrieval | s3GirStorageSize |
| amazonS3Glacier | s3Glacier | s3GlacierStorageSize |
| amazonS3GlacierDeepArhive | s3GlacierDeepArchive | s3DeepArchiveStorageSize |

> **Only `amazonS3Standard` / `s3StandardStorageSize` is capture-verified.** Every other class's size field name in the table above is **inferred from the bundle**, not round-tripped. The SPA matches field names literally, so a wrong name silently zeroes that storage dimension — you get a `$0` storage line for real data (a silent miscompute). Before emitting any non-Standard storage class, capture a HAR of that class to confirm the exact field name, or refuse the class. Intelligent-Tiering (multiple bands) must not be emitted without a capture. After emitting, sanity-check that non-zero storage yields non-zero cost.

### Data Transfer

```jsonc
{
  "serviceCode":  "awsS3DataTransfer",
  "estimateFor":  "awsS3DataTransfer",
  "version":      "0.0.27",
  "region":       "<code>",
  "description":  null,
  "calculationComponents": {
    "dataTransfer": {
      "value": [
        {"entryType": "INBOUND",  "value": "<TB>", "unit": "tb_month", "fromRegion": ""},
        {"entryType": "OUTBOUND", "value": "<TB>", "unit": "tb_month", "toRegion":   "External"}
      ]
    }
  },
  "serviceCost": { "monthly": <computed>, "upfront": 0 }
}
```

Inbound from internet is free. Outbound to internet uses the AWS Outbound tiered pricing. **There is no free GB band in what the calculator applies.** The calculator's data-transfer metered unit map (`datatransfer-calc.json`; source below) charges outbound from the first GB: its first tier `DataTransfer External Outbound Next 10 TB` has `StartingRange: 0` at a non-zero rate ($0.09/GB in us-east-1), followed by `Next 40 TB`, `Next 100 TB`, and `Greater than 150 TB` bands — i.e. band widths 10 TB / 40 TB / 100 TB / 150+ TB. Verified across all 109 regions in the map on 2026-07-13: every first outbound band starts at 0 GB with a non-zero price, and there are **zero** $0 (free) outbound bands. AWS's *published* DT-out free tier is 100 GB/mo, but this map does not encode it, consistent with the calculator's general behaviour of not subtracting free tiers (cf. the SQS free-tier note). Do **not** pre-subtract any free GB; if you believe a free allowance applies, recompute-validate a live capture before relying on the subtraction. Outbound to another region uses cross-region transfer rates (put the destination region code in `toRegion`).

> **Source (verify before relying):** `datatransfer-calc.json` metered unit map, reached via the `awsS3DataTransfer` service definition (`https://d1qsjq9pzbk1k6.cloudfront.net/data/awsS3DataTransfer/en_US.json`, field `mappingDefinitions[].mappingDefinitionURL` = `pricing/2.0/meteredUnitMaps/datatransfer/[currency]/current/datatransfer-calc.json`), fetched from `https://calculator.aws/pricing/2.0/meteredUnitMaps/datatransfer/USD/current/datatransfer-calc.json` (gzip) on 2026-07-13. Field checked: `regions[<region>]["DataTransfer External Outbound Next 10 TB"]` → `{"StartingRange":"0","EndingRange":"10240","price":"0.0900000000"}` (us-east-1).

> **Do not leave `toRegion: ""` — it silently produces a $0 outbound line.** The captured estimate has 100 TB outbound but `serviceCost.monthly: 0` precisely because `toRegion` was empty (the SPA doesn't commit a charge with no destination). For internet egress set `toRegion: "External"` (the value verified working in the VPC `dataTransferVpc` sub-service, which charges correctly); for inter-region set the destination region code. Because the S3 DT sub-service was only captured with an empty destination, **recompute-validate** the share URL after setting a real destination to confirm the outbound charge renders, and never hand off the empty-`toRegion` $0 line for a workload that actually transfers data (it trips the skill's non-zero-cost invariant).

## Pricing API filters

### S3 Standard storage

```
--service-code AmazonS3
--filter "storageClass=General Purpose"
--filter volumeType=Standard
--filter regionCode=<region>
```

Returns three OnDemand priceDimensions for the standard tiers:
- 0–50 TB ($0.023/GB-mo in us-east-2)
- 50–500 TB ($0.022)
- 500+ TB ($0.021)

Walk the user's GB-month across these tiers.

### S3 Standard-IA, Glacier, Deep Archive (per class)

```
--service-code AmazonS3
--filter storageClass=<Infrequent Access | Glacier | Deep Archive>
--filter regionCode=<region>
```

`get-attribute-values --service-code AmazonS3 --attribute storageClass` enumerates the valid values.

### S3 outbound DT to internet

```
--service-code AWSDataTransfer
--filter fromLocation=<regionName>
--filter toLocationType=External
--filter transferType=AWS Outbound
```

Same tiered structure as EC2 DT.

## Multipliers / formula

```
S3 storage tiered cost  = sum over priceDimensions of (gb_in_band * tier_price)
S3 outbound DT cost     = sum over priceDimensions of (gb_in_band * tier_price)
sub.serviceCost.monthly = above
group.serviceCost.monthly = sum of sub.serviceCost.monthly
```

Rounding follows `references/body-schema.md` → "Rounding": round each sub-service total to two decimals first, then sum for the group line item.

## Defaults

| Field | Default |
|---|---|
| storageClass | Standard |
| moveToStorageClassMethod | "No movement required" |
| inbound | 0 TB |
| outbound | 0 TB |
| outbound destination | internet (`toRegion: "External"`) |

## Notes

- The captured estimate has `serviceCost.monthly: 0` for `awsS3DataTransfer` despite 100 TB inbound + 100 TB outbound — because `toRegion: ""` (empty) and the SPA does not commit a charge without a destination. **This is the empty-destination $0 trap**: set `toRegion: "External"` for internet egress (or a region code for inter-region) so the outbound charge actually computes, and recompute-validate. See the Data Transfer shape above.
